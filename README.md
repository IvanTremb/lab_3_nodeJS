## Ход работы

В ходе лабораторной работы разработано приложение «Система управления учебными курсами». Оно позволяет просматривать, добавлять, редактировать и удалять курсы, а также выполнять поиск и фильтрацию по семестру.

Проект разделён на модели, контроллеры и представления. В `models/courseModel.js` хранится массив из пяти исходных курсов. Каждый курс содержит ID, название, преподавателя, количество кредитов, семестр и описание. Маршруты вынесены в `routes/courseRoutes.js`, обработчики запросов — в `controllers/courseController.js`, а страницы — в папку `views`.

В `app.js` настроены Express и шаблонизатор EJS. Для получения данных HTML-форм используется `express.urlencoded()`, а для подключения CSS — `express.static()`. Сервер работает на порту `3000`.

Реализованы следующие маршруты:

| Метод | Маршрут | Назначение |
| --- | --- | --- |
| GET | `/` | Перенаправление на список курсов |
| GET | `/courses` | Просмотр списка, поиск и фильтрация |
| GET | `/courses/new` | Форма добавления курса |
| POST | `/courses` | Сохранение нового курса |
| GET | `/courses/:id` | Просмотр полной информации о курсе |
| GET | `/courses/:id/edit` | Форма редактирования |
| POST | `/courses/:id/edit` | Сохранение изменений |
| POST | `/courses/:id/delete` | Удаление курса |

Данные формы передаются через `req.body`, ID курса получается из `req.params`, а параметры поиска и фильтрации — из `req.query`. Новому курсу автоматически присваивается уникальный ID. После добавления и удаления выполняется переход к списку, после редактирования — к странице обновлённого курса. Перед удалением браузер запрашивает подтверждение.

Поиск выполняется по части названия или имени преподавателя без учёта регистра. Фильтр позволяет выбрать семестр от 1 до 8. Оба условия можно применять одновременно. Если подходящих курсов нет, отображается сообщение «Курсы не найдены».

## Middleware и оформление

В `validateCourse.js` реализована проверка обязательных полей, положительного количества кредитов и целого номера семестра от 1 до 8. При ошибке сервер возвращает статус 400 и повторно показывает форму с сообщениями и введёнными данными. Некорректные данные не сохраняются.

Middleware `logger.js` выводит метод запроса, URL, дату и время. Для отсутствующих страниц и курсов предусмотрена страница 404 с запрошенным адресом. При внутренней ошибке отображается страница 500 без технических подробностей.

Общие элементы страниц вынесены в `header.ejs` и `footer.ejs`. В шапке расположена навигация, в подвале — имя студента, группа и текущий год. В CSS оформлены таблица, формы, карточка курса и сообщения об ошибках. Кнопки просмотра, редактирования и удаления отличаются цветом.

## Запуск и проверка

Из папки `lab_3` приложение запускается командами:

```bash
npm install
npm start
```

Адрес приложения: `http://localhost:3000/courses`.

Для автоматической проверки используется команда `npm test`. Все восемь проверок прошли успешно: проверены основные страницы, операции с курсами, поиск, фильтрация, валидация, логирование, обработка ошибок и безопасное отображение пользовательского текста. Дополнительно в браузере проверены оформление страниц и сохранение полей формы при ошибке.
